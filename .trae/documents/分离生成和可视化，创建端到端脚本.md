## 拆分行为建模部分，创建端到端脚本

### 1. 目录结构设计
```
scripts/
├── step1_1_process_raw.py        # 处理原始数据
├── step1_2_extract_features.py   # 提取特征
├── step1_3_discover_patterns.py  # 运行聚类
├── step2_1_train_model.py        # 训练模型
├── step2_2_generate_samples.py   # 生成样本
├── step2_3_visualize_results.py  # 可视化结果
└── e2e_pipeline.py               # 端到端脚本

data/
├── raw/                         # 原始数据
├── processed/                   # 处理后的数据
└── results/                     # 固定结果目录
    ├── models/                  # 模型文件
    ├── generated/               # 生成的数据
    └── visualization/           # 可视化结果
    └── patterns/                # 行为模式结果
```

### 2. 实现步骤

#### 2.1 创建scripts目录
- 创建scripts目录，将所有脚本移到该目录下

#### 2.2 拆分行为建模部分
- **step1_1_process_raw.py**：处理原始数据
- **step1_2_extract_features.py**：提取特征
- **step1_3_discover_patterns.py**：运行聚类

#### 2.3 创建条件生成部分
- **step2_1_train_model.py**：训练条件扩散模型
- **step2_2_generate_samples.py**：生成样本
- **step2_3_visualize_results.py**：可视化对比

#### 2.4 创建e2e_pipeline.py
- 整合所有步骤
- 使用固定目录，不使用时间戳
- 目录清理逻辑：在生成文件前检查并删除现有文件
- 调用顺序：step1_1 → step1_2 → step1_3 → step2_1 → step2_2 → step2_3

### 3. 脚本功能

#### 3.1 行为建模阶段（step1_x）
- **step1_1_process_raw.py**：处理原始数据，输出到`data/processed/`
- **step1_2_extract_features.py**：提取特征，输出到`data/results/patterns/`
- **step1_3_discover_patterns.py**：运行聚类，输出行为模式到`data/results/patterns/`

#### 3.2 条件生成阶段（step2_x）
- **step2_1_train_model.py**：训练条件扩散模型，输出到`data/results/models/`
- **step2_2_generate_samples.py**：生成样本，输出到`data/results/generated/`
- **step2_3_visualize_results.py**：可视化对比，输出到`data/results/visualization/`

### 4. 端到端脚本功能
- **目录清理**：在每个步骤开始前清理目标目录
- **固定目录**：使用固定目录名称，不使用时间戳
- **整合流程**：一键运行所有步骤
- **清晰阶段划分**：分为行为建模和条件生成两个阶段
- **日志输出**：详细的日志信息
- **错误处理**：完善的错误处理机制

### 5. 使用方法
```bash
# 运行端到端脚本
python scripts/e2e_pipeline.py

# 单独运行某个步骤
python scripts/step1_1_process_raw.py
python scripts/step1_2_extract_features.py
python scripts/step1_3_discover_patterns.py
python scripts/step2_1_train_model.py
python scripts/step2_2_generate_samples.py
python scripts/step2_3_visualize_results.py
```

- 条件生成部分改为step2_x命名，清晰区分两个阶段
- 固定的目录结构，不使用时间戳
- 干净的运行环境，自动清理现有文件
- 一键式操作，简化使用流程
