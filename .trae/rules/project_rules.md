# Trae 项目规则说明文档

## 1. 项目概述

本项目是一个网络模拟参数生成系统，使用现代 Python 技术栈开发，旨在提供高效、可靠的网络模拟数据生成能力。

## 2. 代码规范

### 2.1 注释规范
- **语言要求**：所有注释必须使用中文
- **注释内容**：
  - 类和函数必须包含文档字符串（docstring）
  - 复杂逻辑必须添加行注释
  - 变量命名应清晰，必要时添加注释说明
- **文档字符串格式**：使用 Google 风格的文档字符串

### 2.2 代码风格
- **遵循规范**：采用 Google Python 代码风格
- **格式化工具**：使用 ruff 进行代码格式化和 lint 检查
- **行长度限制**：每行代码不超过 88 个字符
- **缩进**：使用 4 个空格进行缩进
- **引号**：统一使用双引号（""）
- **圈复杂度要求**：函数的圈复杂度不得超过 10
  - 圈复杂度通过 ruff 的 mccabe 规则（C901）进行检查
  - 超过阈值的函数需要进行重构，拆分为多个简单函数
  - 特殊情况下可申请例外，但需经过代码审查批准

## 8. 归一化规范

### 8.1 归一化模块概述
- **功能**：提供统一的数据归一化和反归一化功能，用于网络模拟数据的预处理和生成
- **核心类**：`Normalizer` 类，位于 `network_simulation.condition_generation.normalization` 模块
- **支持的数据类型**：延迟数据、丢包率数据
- **主要功能**：
  - 数据归一化：将原始数据转换为适合模型训练的范围
  - 数据反归一化：将模型生成的数据转换回原始数据范围
  - 参数管理：保存和加载归一化参数
  - 与模型检查点集成：支持从模型检查点加载归一化参数

### 7.2 归一化使用规范

#### 7.2.1 初始化 Normalizer 类
```python
from network_simulation.condition_generation.normalization import Normalizer

# 初始化归一化器，指定合法丢包值列表
normalizer = Normalizer(valid_loss_values)
```

#### 7.2.2 数据归一化
```python
# 归一化延迟和丢包率数据
delay_norm, loss_norm = normalizer.normalize(delay_values, loss_rate_values, use_log_transform=True)
```

#### 7.2.3 数据反归一化
```python
# 反归一化延迟和丢包率数据
delay, loss_rate = normalizer.denormalize(delay_norm, loss_norm)
```

#### 7.2.4 保存归一化参数
```python
# 保存归一化参数到文件
normalizer.save_params("normalization_params.json")
```

#### 7.2.5 加载归一化参数
```python
# 从文件加载归一化参数
normalizer.load_params("normalization_params.json")
```

#### 7.2.6 与模型检查点集成
```python
# 从模型检查点加载归一化参数
normalizer.from_checkpoint(checkpoint)

# 将归一化参数转换为模型检查点格式
checkpoint_params = normalizer.to_checkpoint()
```

### 7.3 归一化参数管理

#### 7.3.1 归一化参数结构
- **delay**：延迟数据的归一化参数，包含：
  - normalization_method：归一化方法（如 'robust'）
  - delay_scaler_center_：RobustScaler 中心值
  - delay_scaler_scale_：RobustScaler 缩放因子
  - robust_scale_min：RobustScaler 输出最小值
  - robust_scale_max：RobustScaler 输出最大值
  - clipped_min：截断后的最小值
  - clipped_max：截断后的最大值
  - original_min：原始数据最小值
  - use_log_transform：是否使用对数变换
- **loss_rate**：丢包率数据的归一化参数，包含：
  - loss_rate_mapping：丢包率到索引的映射
  - valid_loss_values：合法丢包值列表

#### 7.3.2 归一化参数保存
- **文件格式**：JSON 格式
- **保存位置**：建议与模型文件保存在同一目录下
- **命名规范**：使用有意义的名称，如 `normalization_params.json`

#### 7.3.3 归一化参数加载
- **加载时机**：在数据预处理和模型生成时加载
- **加载方式**：使用 `normalizer.load_params()` 或 `normalizer.from_checkpoint()` 方法

### 7.4 归一化最佳实践

#### 7.4.1 何时使用归一化
- **数据预处理**：在模型训练前，对训练数据进行归一化
- **模型生成**：在模型生成数据后，对生成数据进行反归一化
- **数据可视化**：在可视化前，对数据进行适当的缩放

#### 7.4.2 确保归一化和反归一化的一致性
- **使用相同的参数**：确保归一化和反归一化使用相同的参数
- **保存和加载参数**：使用 `save_params()` 和 `load_params()` 方法管理参数
- **与模型检查点集成**：将归一化参数保存到模型检查点中

#### 7.4.3 处理不同类型的数据
- **延迟数据**：使用对数变换 + RobustScaler 归一化
- **丢包率数据**：使用序数编码 + Min-Max 缩放
- **其他数据**：根据数据特性选择合适的归一化方法

#### 7.4.4 避免归一化错误
- **不要对同一数据重复归一化**
- **确保反归一化参数与归一化参数匹配**
- **检查归一化后的数据范围**
- **验证反归一化后的数据与原始数据的一致性**

### 7.5 归一化常见问题

#### 7.5.1 反归一化后的数据与原始数据差异较大
- **原因**：归一化参数不匹配或数据范围超出预期
- **解决方法**：
  - 确保使用正确的归一化参数
  - 检查数据范围是否在预期范围内
  - 验证归一化和反归一化过程的一致性

#### 7.5.2 归一化后的数据分布不均匀
- **原因**：数据本身分布不均匀或归一化方法选择不当
- **解决方法**：
  - 尝试使用不同的归一化方法
  - 对数据进行预处理，如对数变换
  - 考虑使用鲁棒性更强的归一化方法，如 RobustScaler

#### 7.5.3 归一化参数保存和加载失败
- **原因**：文件路径错误或参数格式不匹配
- **解决方法**：
  - 检查文件路径是否正确
  - 确保参数格式符合要求
  - 使用 try-except 块处理异常

## 12. 上下行数据处理规范

### 12.1 数据类型
- **上行数据**：上行时延（delay1）、上行丢包率、上行带宽
- **下行数据**：下行时延（delay2）、下行丢包率、下行带宽

### 12.2 数据处理要求
- **数据加载**：支持加载包含上下行数据的原始文件
- **数据预处理**：对上下行数据分别进行预处理
- **特征提取**：对上下行数据分别提取特征
- **带宽处理**：上下行带宽需要处理，但不作为模式发现和模型训练的输入
- **模式发现**：基于上下行时延和丢包率进行模式发现，不使用带宽数据
- **模型训练**：基于上下行时延和丢包率进行模型训练，不使用带宽数据
- **可视化**：支持上下行数据的可视化，包括时延、丢包率和带宽
