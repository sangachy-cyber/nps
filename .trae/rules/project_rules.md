# Trae 项目规则说明文档

## 1. 项目概述

本项目是一个网络模拟参数生成系统，使用现代 Python 技术栈开发，旨在提供高效、可靠的网络模拟数据生成能力。

## 2. 代码规范

### 2.1 注释规范
- **语言要求**：所有注释必须使用中文
- **注释内容**：
  - 类和函数必须包含文档字符串（docstring）
  - 复杂逻辑必须添加行注释
  - 变量命名应清晰，必要时添加注释说明
- **文档字符串格式**：使用 Google 风格的文档字符串

### 2.2 代码风格
- **遵循规范**：采用 Google Python 代码风格
- **格式化工具**：使用 ruff 进行代码格式化和 lint 检查
- **行长度限制**：每行代码不超过 88 个字符
- **缩进**：使用 4 个空格进行缩进
- **引号**：统一使用双引号（""）

## 3. 日志打印规范

### 3.1 日志模块使用
- **必须使用**：项目提供的封装好的 logger 模块
- **导入方式**：
  ```python
  from network_simulation.utils.logger import get_logger
  logger = get_logger(__name__)
  ```
- **日志级别**：
  - DEBUG：调试信息，用于开发阶段
  - INFO：普通信息，用于记录正常流程
  - WARNING：警告信息，用于潜在问题
  - ERROR：错误信息，用于错误情况
  - CRITICAL：严重错误，用于导致程序终止的情况

### 3.2 日志记录规范
- **避免使用**：print() 语句进行日志输出
- **日志内容**：应包含足够的上下文信息，便于调试和追踪
- **格式要求**：使用 logger 模块自动处理的格式，无需手动添加时间戳等信息

## 4. 依赖管理

### 4.1 依赖管理工具
- **必须使用**：uv 作为依赖管理工具
- **配置文件**：pyproject.toml 和 uv.lock

### 4.2 安装规范
- **安装命令**：
  ```bash
  uv install
  ```
- **开发依赖安装**：
  ```bash
  uv install -d
  ```

### 4.3 依赖添加规范
- **添加依赖**：
  ```bash
  uv add <package-name>
  ```
- **开发依赖添加**：
  ```bash
  uv add -d <package-name>
  ```

## 5. 运行规范

### 5.1 运行方式
- **必须使用**：uv run 命令运行项目
- **运行示例**：
  ```bash
  uv run python scripts/e2e_pipeline.py
  ```
- **命令行工具运行**：
  ```bash
  uv run network-simulate <command>
  ```

## 7. 文件目录规范

### 7.1 主要目录结构
```
NPS/
├── .trae/            # Trae 相关文件
├── data/             # 数据目录
│   └── raw/          # 原始数据
├── docs/             # 文档目录
├── examples/         # 示例代码
├── scripts/          # 脚本文件
├── src/              # 源代码
│   └── network_simulation/  # 主包
├── tests/            # 测试代码
└── tmp/              # 临时文件（如果需要）
```

### 7.2 目录用途说明
- **.trae/**：Trae 工具生成的计划和文档
- **data/**：存放项目数据，包括原始数据和处理后的数据
- **docs/**：存放项目文档
- **examples/**：存放示例代码和使用案例
- **scripts/**：存放可执行脚本，包括各步骤的执行脚本
- **src/**：存放项目源代码，采用包结构组织
- **tests/**：存放测试代码
- **tmp/**：存放临时文件，如中间结果、日志等（若需创建）

### 7.3 文件命名规范
- **Python 文件**：使用小写字母和下划线组合（snake_case）
- **脚本文件**：使用小写字母、数字和下划线组合，清晰表达功能
- **数据文件**：使用有意义的名称，可包含时间戳

## 8. 测试规范

### 8.1 测试框架
- **使用 pytest** 作为测试框架
- **测试文件存放**：所有测试文件必须放在 tests/ 目录下

### 8.2 测试文件命名
- **命名格式**：`test_<module_name>.py`
- **示例**：`test_data_loader.py`、`test_diffusion_model.py`

### 8.3 测试覆盖要求
- **新增模块**：必须添加对应的测试文件和测试用例
- **测试覆盖**：争取达到 80% 以上的代码覆盖率
- **测试类型**：
  - 单元测试：测试单个函数或类
  - 集成测试：测试模块间的交互
  - 端到端测试：测试完整流程

### 8.4 测试运行
- **运行所有测试**：
  ```bash
  uv run pytest
  ```
- **运行特定测试**：
  ```bash
  uv run pytest tests/test_module.py
  ```
- **生成覆盖率报告**：
  ```bash
  uv run pytest --cov=src
  ```
